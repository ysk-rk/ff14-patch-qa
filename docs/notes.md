# 開発メモ

FF14 黄金のレガシー（7.0〜7.57）のパッチノートに、出典付きで答える Q&A アプリ（RAG）の開発記録。

## 構成

- データ: ロードストーンのパッチノート 23本（7.0〜7.57）
- バックエンド: Python、FastAPI
- 検索: multilingual-e5-small（埋め込み）、Chroma（ベクトルDB）、rank-bm25（キーワード検索）を RRF で合わせる
- テスト: pytest、GitHub Actions
- 回答: Gemini API（gemini-3.8-flash、混雑時は gemini-3.5-flash-lite）
- プロンプト: 質問の種類をコードで決め、今の値の質問は v5、何が変わったか・いつ変わったかの質問は v4 を使う（auto）
- フロントエンド: TypeScript、React、Vite

## 2026-10-22 データの取得元を Steam からロードストーンに変更

最初は Steam のニュース API（appid 39210）からパッチノートを取得した。

- 17件取得できたが、1件あたり 300〜1,200文字しかなかった
- 中身は概要だけで、全文はロードストーンへのリンクになっていた
- 大型パッチ（7.1〜7.5）が取得できていなかった

ロードストーンの「パッチノート＆パッチ特設サイト一覧」には、7.0〜7.57 の23本が日本語の全文で載っていたため、こちらに切り替えた。

取得する前に、次の3つを確認した。

- The Lodestone ガイドライン: 禁止事項は投稿に関するものだけで、自動取得を禁止する文はない
- ファイナルファンタジーXIV 利用規約 第7条: RMT などが禁止事項。自動取得を直接禁止する文はない
  - (3)「本サービス外で何らかの利益を得るために、本サービスを利用する行為」は範囲がはっきりしないが、営利目的ではなく、本文も公開しないため、問題になる可能性は低いと判断
- robots.txt: 置かれていない（404）

取得のしかた:

- 23ページを1回だけ取得し、1ページごとに5秒あける
- 保存済みのページは二度と取りに行かない
- 取得した本文は GitHub に上げない（.gitignore で data/ を除外）

## 2026-10-23 HTML の作りに合わせて見出しの階層を修正

最初は h2 を一番上、h3 を2番目として扱っていたため、PvE のジョブ調整の見出しが「その他 > … > モンク」になっていた。

HTML を調べると、見出しは4段階で、一番上の分類は h2 ではなく class 付きの h3 だった。

| 階層 | タグ | 例 |
| --- | --- | --- |
| 大分類 | h3.mdl-title__ancher | イベント関連、バトル関連、アイテム関連 |
| 中分類 | h2 | クエスト関連、PvP全般、その他 |
| 項目 | その他の h3 | アクション／特性において、以下の調整が行われます。 |
| ジョブ名など | h4 | モンク |

「バトル関連」のすぐ下には中分類がなく、前の大分類の中にあった h2「その他」が残っていた。タグ名と class で階層を決めるように直し、PvE は「バトル関連 > … > モンク」、PvP は「バトル関連 > PvP全般 > … > モンク」になった。

チャンクの作り方:

- 本文の入れ物（div.news__detail__wrapper）の中だけを読む
- 各チャンクの先頭に、パッチ番号と見出しの階層を付ける
- 表は Markdown の表に変換し、途中で切らない。1,500文字を超える表だけ行の区切りで分け、分けたそれぞれに見出しの行を付け直す
- 矢印の画像だけが入った列は消す

## 2026-10-24 見出しだけの項目が消えていた不具合

- 「分解スキルの上限値が 720 → 740 に引き上げられます」のように、見出しそのものが変更内容になっている項目が、チャンクに入っていなかった
- 原因: 見出しの下に本文か表があるときだけチャンクを作っていた

## 2026-10-24 評価用データ 20問

- PvE で2回以上調整され、最後の調整が 7.4 以降のスキルを、チャンクの表から自動で探して候補にした（55件）
- 正解は、パッチごとの「変更前」と「変更後」の数字がつながっているかで確かめた（見落とした調整があればずれる）

見つかった「わな」:

- 後のパッチで別の項目だけが変わるスキルがある（例: 祖霊の蛇【壱】は、威力の最後の変更が 7.2、減衰率の最後の変更が 7.5）。「一番新しいパッチを見ればいい」と考えると間違える

- 分解スキルの上限値は大型パッチのたびに上がっていた（650 → 780）。最初に考えた正解の 740 は古い値だった

次にやること:

1. 20問を自動で流して、検索と回答の正解率を出すスクリプトを作る
2. 採点は「数字が合っているか」と「今の値として答えているか」を分ける
3. モデルごとの正解率を比べる
4. プロンプトの「一番新しいパッチの情報を今の情報とする」を、スキル単位ではなく項目単位（威力・減衰率など）で考えるように直す

## 2026-10-25 v2 で q002 が答えられなくなっていた

- 画面で「PvPのモンクの夢幻闘舞は何が変わった？」を聞くと、「分かりませんでした」と答えた

  - 採点: history の質問は、必要なパッチ番号がすべて回答に入っているかで採点する
